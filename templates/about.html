About CourseConnect

A high-concurrency academic registration system engineered with Python Flask, MySQL, and clean transactional database principles.

Relational Integrity
3NF Normalized Schema
OWASP Secure
Parameterized SQL & Hashing
ACID Transactions
Zero Over-Subscription

1. Relational Database Design

The system relies on a relational MySQL database named course_registration with strict referential integrity, foreign key cascades, unique constraints, and check constraints to prevent race conditions during seat assignment.

Database Tables & Constraints:

  • students: Contains primary key student_id, unique email, password_hash (scrypt/PBKDF2 encrypted), and role (student vs administrator).
  • courses: Contains primary key course_id, unique course_code, max_seats, and available_seats protected by database check constraint CHECK (available_seats >= 0 AND available_seats <= max_seats).
  • enrollments: Junction entity connecting students and courses with composite unique key (student_id, course_id) to eliminate duplicate active registrations.

2. Transactional Concurrency Control

Course enrollment operations are executed inside atomic database transactions. The system locks row records during reservation, verifies available seats, and decrements available_seats in lockstep with the enrollment insert. If two students request the final seat simultaneously, the database guarantees that only one succeeds and the other receives a descriptive error without data corruption.

3. Golden Metallic Button Design System

Built according to the specification with a metallic gold gradient (#B8860B, #D4AF37, #F5D76E), high-contrast navy text, specular highlight sheen on hover, and smooth cubic-bezier transitions. Destructive actions utilize distinct danger warning styling to prevent accidental deletions.
